# C 端内容门户需求说明

## 审阅结论与已确定基线

本文件已按当前仓库的后端模型、B 端实现和根目录规范完成复核。原始需求方向正确，但必须区分“后台内公开”和“允许匿名互联网访问”：现有 `isPrivate=false` 只表示资源可被具有相应菜单与动作权限的登录用户访问，不能单独作为 C 端发布条件。

本次按用户“按照推荐方案实施”的确认，固定以下基线，后续开发不再以这些事项作为阻塞问题：

1. 仓库根目录下的 `portal/` 本身就是 C 端项目根目录，`package.json` 名称使用 `portal`；禁止再创建 `portal/collector-portal/`、`portal/portal/` 或其他嵌套项目目录。
2. 首期沿用 B 端品牌 `HuaJian_AI`，C 端页面说明使用“内容门户”；品牌名、站点说明、Logo、默认分享图和联系入口集中放在站点配置中，后续可单点替换。
3. 文章只有同时满足 `status="已发布"`、`isPrivate=false`、`portalVisible=true` 才能在 C 端展示。
4. 图片瀑布流只展示允许浏览器安全预览的公开图片；PDF、Office、文本等资源进入独立资源页，程序和脚本类文件首期禁止匿名发布与下载。
5. 首期不复制大型开源模板，以现有 Next.js 技术栈自主实现；可参考 MIT、Apache-2.0 或 BSD 许可证项目，引用代码时必须保留许可证和来源记录。
6. 客服入口作为可配置增强项，复用现有客服聊天边界与组件能力，默认由环境变量控制启停，不影响门户核心页面上线。
7. UI 首期支持 `zh-CN`、`en-US`、`ja-JP`；简体中文是默认语言、源文案和最终回退语言。

## 项目定位

C 端项目是面向普通访问者的公开内容门户，用于展示经 B 端明确发布到门户的文章、图片和文件资源。它与现有后台前端、后端服务同属一个采集数据管理平台，但业务边界不同：

- `backend/` 继续作为统一 API 服务和数据来源。
- `frontend/` 继续作为 B 端管理后台，负责内容、文件、权限、用户以及门户发布状态管理。
- 新增 `portal/` 作为 C 端前端项目，负责公开展示、SEO、跨端访问体验和多语言内容入口。

C 端不复制业务数据、不直连 SQLite、不复用后台登录 Cookie，也不提供内容编辑能力。所有可见内容均通过后端 `/api/public/*` 只读接口获取，后台管理接口继续维持原鉴权和权限边界。

## 核心目标

1. 展示 B 端沉淀的公开资源，包括文章、图片、文件说明和分类聚合。
2. 做好 SEO，使首页、文章详情、分类页、图片页都拥有可索引的真实 URL。
3. 提供桌面端、平板端、移动端一致可用的响应式体验。
4. 提供平滑页面切换、筛选切换、卡片进入和主题切换动画，避免生硬跳变。
5. 提供主题切换、高斯模糊视觉层、i18n 多语言切换。
6. 严格保护后台资源，只展示已明确发布到门户、未删除且允许预览的内容。
7. 让 B 端可以控制资源是否发布到 C 端，并在取消发布后立即停止新的公开访问。
8. 在常规移动网络下保持可接受的首屏速度、图片加载性能和页面稳定性。

## 首期范围与边界

首期必须交付：

- 首页、文章列表、文章详情、图片瀑布流、资源列表、分类、搜索、关于页面。
- B 端文章和文件的门户发布控制，以及后端只读公开 API。
- 三语言 UI、三套主题、平滑过渡、高斯模糊、响应式布局和无障碍基础能力。
- metadata、canonical、hreflang、Open Graph、JSON-LD、sitemap、robots 和 RSS。
- 隔离环境测试、生产构建、桌面端与移动端官方 Browser 验收。

首期不包含：

- 用户注册、登录、评论、点赞、收藏同步、付费内容和用户投稿。
- 自动机器翻译文章正文；业务内容保持 B 端录入的原始语言。
- 任意第三方脚本、任意文件类型的匿名下载、C 端内容编辑和后台权限复用。
- 原生 App、离线完整阅读、复杂推荐算法和独立搜索引擎。

## 技术方案

- 项目根目录：`portal/`，应用源码、配置、依赖清单和锁文件直接放在该目录下，不增加第二层项目文件夹。
- 技术栈：Next.js 16 App Router + React + strict TypeScript + Tailwind CSS 4 + Lucide React。
- i18n：使用 `next-intl` 管理语言路由、消息资源和服务端格式化，不自建翻译引擎。
- 动画：CSS transition、transform 和 opacity 优先；页面切换使用与 App Router 兼容的轻量客户端过渡层，不为简单动画引入大型动效框架。
- 图片：使用 Next.js Image 和后端受控公开媒体地址；瀑布流以已知宽高比预留空间，避免图片加载后跳动。
- 开发端口：默认 `http://localhost:3001`，避免与 B 端 `frontend/` 的 `3000` 冲突。
- 后端地址：通过 `NEXT_PUBLIC_API_BASE_URL` 配置，默认 `http://localhost:8080`。
- 路由模式：采用真实 URL 路由，不沿用 B 端 `activePage` 单页切换模式。
- UI 策略：不引入重量级新 UI 框架；沿用现有前端的技术风格，但视觉语言更偏内容站、公开站和阅读体验。
- 工程关系：`portal/` 与 `backend/`、`frontend/` 一样独立安装、构建和运行，拥有自己的 `package.json` 与锁文件，不在根目录混装依赖。
- 代码规范：继承根 `AGENTS.md`；C 端新增类型、组件、钩子、服务函数、共享状态和页面内部声明时使用有业务含义的命名与简体中文 JSDoc/解释性注释。

- SEO、三语言、主题、高斯模糊、动画、响应式和无障碍规则。

## 开源二次开发策略

可以参考轻量开源内容站或 Next.js 官方示例，但不建议直接套用重模板。实施原则：

- 优先保持与现有 `frontend/` 技术栈一致。
- 不引入新的大型 UI 体系。
- 如需使用开源模板，必须确认许可证、依赖体积和可维护性。

## 信息架构

### 路由总则

- 所有可索引页面的规范地址统一使用 `/{locale}/...`，例如 `/zh-CN/articles`。
- `/` 仅负责根据已验证的语言 Cookie 或 `Accept-Language` 跳转；没有有效偏好时跳转到 `/zh-CN`。
- 不支持的语言段返回 `404`，不能把任意字符串静默当成语言。
- 语言切换导航到当前内容的等价语言 URL；不存在等价内容时回到目标语言首页。
- 列表分页使用 `?page=2` 等真实 URL；筛选、排序和搜索参数必须可以分享、刷新和浏览器回退。

### 首页 `/{locale}`

首页是 C 端第一入口，以图片瀑布流为核心视觉，直接展示门户的精选图片资源。设计原则：简洁实用、内容优先、不花里胡哨。

需要包含：

- 顶部导航：品牌、首页、文章、图片、资源、分类、关于、搜索入口、语言切换、主题切换。采用半透明高斯模糊背景，滚动时保持可读性。
- 首屏主区域：**响应式图片瀑布流**，直接展示精选或最新的公开图片，桌面端 3-4 列、平板 2-3 列、移动端 1-2 列。
- 简洁数据概览：公开图片数、公开文章数、公开资源数和分类数，使用卡片形式在瀑布流上方或侧边展示，不占用过多视觉空间。
- 瀑布流交互：图片懒加载、模糊占位、悬停轻微缩放效果、点击打开预览浮层。
- 最新文章区（可选）：在瀑布流下方展示 4-6 篇最新文章卡片，包含标题、摘要、分类、发布时间。
- 推荐分类快速入口：在页面底部或侧边展示热门分类标签，点击跳转到对应分类页。
- 首屏直接呈现真实图片内容，避免大段空白、装饰性 Hero 区或营销文案。
- 所有过渡动画使用平滑的 CSS transition，避免生硬跳变，支持 `prefers-reduced-motion`。

### 图片页 `/{locale}/images`

用于展示公开图片资源。

需要包含：

- 响应式瀑布流布局。
- 图片懒加载和模糊占位。
- 分类筛选、关键词搜索、排序。
- 图片预览浮层。
- 文件名称、分类、描述、发布时间、宽高和替代文本。
- 移动端单列或双列瀑布流，禁止横向溢出。
- URL 保留分类、关键词、排序和页码；无限滚动只能作为分页之上的体验增强。
- 预览支持上一张、下一张、缩放、拖动、`Esc` 关闭和移动端手势；切换图片时不改变底层页面滚动位置。

### 文章列表 `/{locale}/articles`

用于展示公开文章。

需要包含：

- 文章卡片列表。
- 分类筛选。
- 关键词搜索。
- 最新、热门、推荐排序。
- 空状态、加载状态、错误状态。
- 服务端分页；可在前端增强为“加载更多”，但每一页必须仍有可访问、可索引的独立 URL。

### 文章详情 `/{locale}/articles/[id]/[slug]`

用于展示单篇公开文章。

需要包含：

- 服务端生成 `metadata`。
- 标题、摘要、作者、分类、发布时间、更新时间、阅读量。
- 正文渲染，兼容 B 端文章内容中的图片。
- 目录锚点和阅读进度。
- 相关文章推荐。
- Open Graph、JSON-LD、canonical。
- `id` 是稳定查询键，`slug` 由标题生成并提升可读性；slug 缺失或不匹配时 `308` 跳转到当前规范地址。
- 提供复制链接和系统分享入口；不强制接入第三方分享脚本。

### 分类页 `/{locale}/categories/[category]`

用于聚合某一分类下的公开文章和图片。

需要包含：

- 分类说明。
- 分类下文章。
- 分类下图片。
- SEO metadata。
- 分类标识使用稳定的 URL 编码值，不使用翻译文案作为数据库键或查询规则。

`/{locale}/categories` 提供全部公开分类入口，并按文章、图片和资源数量展示，不能只存在无法从导航到达的动态分类详情页。

### 搜索页 `/{locale}/search`

用于跨文章和公开文件搜索。

需要包含：

- 搜索输入框。
- 搜索结果分组：文章、图片、文件。
- 空状态与推荐内容。
- 搜索参数写入 URL，便于分享和回退。
- 搜索结果页输出 `noindex,follow`，防止大量关键词组合形成低质量索引页。

### 资源页 `/{locale}/resources`

用于展示经 B 端明确发布到门户的非图片文件。

需要包含：

- 按分类、文件类型、关键词和时间筛选。
- 文件名称、说明、类型、大小、发布时间和可用操作。
- PDF 可在安全响应头下预览；Office、压缩包等只提供受控下载；程序、脚本、HTML 和 SVG 首期禁止匿名发布。
- 下载前由公开 API 再次校验门户可见状态，禁止直接拼接物理文件地址。
- 搜索、筛选、空状态、错误状态和分页体验与文章、图片页保持一致。

### 关于页 `/{locale}/about`

用于介绍平台公开展示范围和联系入口。

需要包含：

- 平台介绍。
- 公开资源说明。
- 隐私说明。
- 可选客服或联系入口，但不得混用内部聊天业务状态。

### 系统页面

- `not-found`：资源不存在、已取消发布或无权公开访问时使用统一 `404`，不透露后台是否存在该资源。
- `error`：服务异常时提供重试和返回入口，不显示堆栈、内部路径或原始后端错误。
- `loading`：使用稳定尺寸的骨架或占位，不能引发布局跳动。
- 离线状态：提示网络不可用并允许重试，不把离线误报为“没有内容”。

## 门户发布模型与 B 端联动

### 数据字段

文章和文件均新增以下字段，迁移必须幂等且不得通过删除数据库处理失败：

- `portalVisible`：是否允许匿名 C 端访问；SQLite 列 `portal_visible` 默认 `0`，历史记录迁移后全部保持不发布。
- `portalFeatured`：是否作为首页或分类精选；SQLite 列 `portal_featured` 默认 `0`，只有门户可见资源才能设为精选。
- `portalPublishedAt`：首次发布到门户的时间；SQLite 列 `portal_published_at` 允许为空，用于排序和 SEO 的 `datePublished`。

文章额外新增 `contentLocale`，SQLite 列 `content_locale` 默认 `zh-CN`，用于标记正文实际语言并生成正确的 `lang` 与结构化数据；该字段不代表系统会自动翻译正文。

公开图片在上传时解析并保存原始宽高，SQLite 列为 `image_width`、`image_height`（API 字段 `imageWidth`、`imageHeight`），探测尺寸不修改原文件。文件 MIME 类型当前以客户端上传时声明的 `Content-Type` 为准，未做扩展名与文件头二次判定。新增列和索引必须在迁移 SQL 旁写明中文用途、关联和访问规则。

文章 `portalPublishedAt` 在首次发布到门户时写入；取消发布时被清空，重新发布时重新写入当前时间，后续变化使用 `updatedAt` 表达。文件当前不写入或更新 `portal_published_at`（上传与元数据更新均不维护该列），公开文件列表的 `publishedAt` 因而为零值时间。`slug` 不新增数据库列，由公开层根据标题确定性生成，查询仍以稳定数字 `id` 为准。文章 `coverImage` 首期从正文中第一张满足公开条件的图片派生，没有可用图片时该字段为空并由 C 端使用站点默认图。

### 发布条件

- 文章：`portalVisible=true`、`isPrivate=false`、`status="已发布"`。
- 图片：`portalVisible=true`、`isPrivate=false`、`deletedAt IS NULL`，且 `content_type` 以 `image/` 为前缀。
- 其他文件（资源）：`portalVisible=true`、`isPrivate=false`、`deletedAt IS NULL`，且 `content_type` 不以 `image/` 为前缀。
- `portalFeatured=true` 不能绕过任何发布条件。
- 任何条件不再满足时，公开 API 必须立即按未发布处理；后台仍保留原记录和原所有权。

### B 端操作

- 文章和文件管理增加“发布到门户”“门户精选”控件，并清晰显示当前门户状态。
- 新增稳定动作权限 `articles.portal-publish`、`files.portal-publish`；只有具有对应动作权限且满足原所有权/管理员规则的用户可以更改门户状态。
- 普通编辑接口即使收到门户字段，也不得让无发布权限用户越权修改。
- 文章切换为非“已发布”、资源切换为私密或文件进入回收站时，自动取消门户可见和精选状态；恢复后不得自动重新发布。
- 发布文章前检查正文引用的本地媒体（未发布、私密、删除或不安全的本地资源需在 B 端提示）当前尚未实现，列为后续增强。
- 文章编辑表单增加正文语言选择，默认 `zh-CN`；该值受支持语言白名单校验，不能用翻译后的语言名称作为数据库值。
- 发布、取消发布和精选变更接入现有访问/操作审计能力当前尚未实现，列为后续增强；任何审计均不记录文件物理路径。

## 后端公开 API 需求

现有 `/api/articles` 和 `/api/files` 需要登录、菜单权限和动作权限，不能直接作为 C 端公开接口。C 端需要新增只读公开 API。

### 通用契约

- 所有接口位于 `/api/public`，仅支持公开读取，不接受后台会话作为提权依据。
- 列表统一返回 `{ "items": [], "pagination": { "page": 1, "pageSize": 24, "total": 0, "totalPages": 0 } }`。
- `page` 从 `1` 开始；默认 `pageSize=24`，最大 `50`；`page` 与 `pageSize` 非法时回退到默认值，不返回 `400`。
- 错误至少返回稳定 `code` 和可记录的 `error`，C 端根据 `code` 映射当前语言文案，不直接展示内部错误。
- 时间使用 UTC RFC 3339（内部按 RFC 3339Nano 存储），字段使用 camelCase；API 不根据 UI 语言翻译用户生成内容、分类或业务状态。
- 列表接口不返回文章完整正文、存储名称、物理路径、所有者 ID、后台权限字段或删除信息。
- 公开详情不存在、已取消发布、私密或已删除时统一返回 `404`。

## 数据安全要求

- C 端不得访问需要后台 Cookie 的管理接口。
- C 端不得展示 `portalVisible=false` 或 `isPrivate=true` 的文章、图片和文件。
- C 端不得展示已软删除文件。
- C 端不得暴露 `storageName`、物理路径或上传目录结构。
- 私密资源和不存在资源对外均可返回 `404`，避免泄露资源存在性。
- 后端必须基于数据库记录的 `storage_name` 拼接物理路径，公开接口只接收数字 ID，不得接收相对路径、绝对路径或存储文件名参数。
- 文章正文按当前实际存储格式视为 HTML，使用白名单清洗方案移除 `script`、事件属性、危险 URL、任意 iframe 和可执行嵌入；禁止把原始正文直接传给 `dangerouslySetInnerHTML`。
- 正文中的本地 `/api/files/:id/preview` 与 `/api/files/:id/thumbnail` 引用重写为对应公开媒体 URL，并逐个校验文件门户发布条件；不满足条件的媒体移除。
- 外部媒体当前允许 `http://` 与 `https://` 白名单协议；浏览器直接请求外部资源，不建设可访问任意 URL 的服务端代理，避免 SSRF。生产 CSP 必须限制脚本、连接、图片、媒体和 frame 来源。
- 文件真实类型当前以客户端上传时声明的 `Content-Type` 为准；扩展名与文件头联合检测列为后续增强。
- `/api/public/*` 当前未配置独立速率限制；搜索关键词长度受限、分页上限为 50；接口不得返回 SQL、堆栈、内部路径或鉴权细节。
- 生产 CORS 仅允许明确配置的门户 Origin；公开可读不等于允许任意站点携带凭证跨域调用，响应不得设置后台会话 Cookie。
- 浏览器验收和测试不得删除、重置、覆盖 `backend/data/` 和 `backend/uploads/` 中的业务数据。
- 如需联调后端，必须使用 `.workspace-temp/` 下的隔离 SQLite 和上传目录。

## SEO 要求

- 首页、文章列表、图片页、资源页、分类页、文章详情均由服务端输出可用正文和 metadata；不得依赖客户端请求完成后才出现主要可索引内容。
- 文章详情必须生成唯一 `title`、`description`、`canonical`。
- 支持 Open Graph 和 Twitter Card。
- 支持 JSON-LD：
  - 首页可使用 `WebSite`
  - 文章详情使用 `Article`
  - 面包屑使用 `BreadcrumbList`
- 自动生成 `sitemap.xml`。
- 自动生成 `robots.txt`。
- 通用多语言页面输出 `zh-CN`、`en-US`、`ja-JP` 和 `x-default` 的 `alternate` 链接；文章详情只有存在真实翻译关系时才输出跨语言 `hreflang`，不能把同一篇未翻译正文伪装成三份翻译。
- 图片资源需要合理 `alt` 文本。
- 生产环境必须配置绝对 `NEXT_PUBLIC_SITE_URL`，canonical、sitemap、RSS 和分享图不得使用 `localhost` 或请求头猜测出的不可信 Host。
- sitemap 只包含当前满足门户发布条件的规范 URL，并包含准确 `lastModified`；取消发布后应在缓存失效窗口内移除。
- `/search`、任意预览浮层 URL、错误页和无法形成稳定规范地址的筛选组合使用 `noindex`。
- 分页页面使用自身 canonical，第一页不能同时以无参数和 `?page=1` 两个地址被索引。
- 提供 `/{locale}/feed.xml` RSS/Atom 订阅，内容只包含已发布文章摘要和规范详情 URL。
- 默认分享图、文章封面和结构化数据图片必须是真实可访问的位图资源；没有封面时使用站点默认分享图。
- 结构化数据必须与页面可见内容一致，不能生成页面上不存在的作者、日期、评分或统计值。

## i18n 要求

首期语言：

- `zh-CN`
- `en-US`
- `ja-JP`

规范路由：

- `/zh-CN`
- `/en-US`
- `/ja-JP`

要求：

- 所有用户可见 UI 文案从按领域分组的语义翻译键读取，包括导航、按钮、占位符、校验、加载、空、成功、错误、超时、离线、提示、工具提示和无障碍名称。
- 默认语言、源文案和最终回退语言为 `zh-CN`；持久化值必须经过 `SUPPORTED_LOCALES` 白名单验证，非法值回退到 `zh-CN`。
- URL 语言段是当前页面语言的唯一事实来源；语言偏好写入 `portal-locale` Cookie，供 `/` 服务端跳转使用，避免首屏先显示错误语言再闪烁。
- 语言选择器显示清晰的语言名称，不能只显示国旗；切换后保留当前筛选、分页和可等价访问的内容位置。
- 翻译资源使用语义键和命名占位符，不拼接翻译片段；复数、日期、相对时间、数字、百分比和文件大小使用 `Intl.*` 或 `next-intl` 格式化。
- 每个页面设置正确的 `<html lang>`；文章正文容器额外使用文章的 `contentLocale`。用户生成的标题、正文、分类和文件说明保持原文，不把 API 值当翻译键。
- 三套 UI 消息必须完整加载；开发环境缺键显示明确警告，生产环境按确定顺序回退，不能静默显示空白。
- 英文和日文长文案必须在移动导航、筛选栏、按钮、对话框和卡片中完成不截断、不重叠验收。
- 首期不自动翻译业务内容；未来若增加多语言文章，使用明确翻译组关联独立文章记录，不覆盖原文，也不依赖标题判断翻译关系。

## 主题要求

至少支持：

- 浅色主题。
- 深色主题。
- 海洋品牌主题，与 B 端默认品牌色保持家族一致但降低后台工具感。
- 跟随系统选项，映射到浅色或深色主题。

要求：

- 使用 CSS 变量维护主题色。
- 主题偏好以独立键 `portal-theme` 持久化到 `localStorage`，不得覆盖 B 端的 `admin-theme`。
- 首屏加载前应用主题，避免闪烁。
- 主题切换带柔和过渡动画。
- 图片、卡片、浮层、导航栏在不同主题下都要保持可读性。
- 主题控制使用图标、色板和明确可访问名称；颜色不能成为表达状态的唯一方式。
- 同步设置 `color-scheme` 和移动浏览器 `theme-color`；系统主题变化时，仅在用户选择“跟随系统”后实时响应。
- 三套主题均使用中性色作为页面基础，并搭配至少一个独立强调色，避免整个界面只由单一蓝色或紫色调构成。

## 动画与交互要求

- 页面切换需要平滑过渡。
- 图片卡片进入时使用轻量渐入和位移动画。
- 筛选条件变化时避免布局突然跳动。
- 图片预览浮层使用高斯模糊背景。
- 导航栏滚动状态变化应平滑。
- 主题切换不能出现大面积闪烁。
- 所有动画必须支持 `prefers-reduced-motion: reduce`，在用户减少动态效果时关闭或弱化动画。
- 常规交互动画建议控制在 `160ms` 到 `280ms`，图片预览大型浮层不超过 `360ms`；动画不能阻塞导航、点击或浏览器回退。
- 优先动画 `transform` 和 `opacity`，避免连续动画宽高、阴影模糊半径或大面积 `filter` 导致掉帧。
- 列表加载、语言切换和返回上一页时尽量保留滚动位置与已选筛选条件；页面切换不能造成双重滚动条或内容闪白。
- hover 效果只作为有鼠标设备的增强，触摸设备上的所有核心操作必须始终可发现、可点击。

## 高斯模糊视觉要求

可使用场景：

- 顶部导航栏。
- 搜索面板。
- 图片预览浮层背景。
- 筛选工具栏。
- 首页局部信息面板。

限制：

- 不用高斯模糊遮挡关键正文。
- 不让模糊层造成低对比度。
- 移动端减少过重模糊，避免性能问题。
- 使用 `backdrop-filter` 时必须提供不透明或半透明纯色回退，浏览器不支持模糊时仍保持清晰层级和对比度。
- 桌面端模糊半径建议 `12px` 到 `20px`，移动端建议不超过 `12px`；不在长列表的每张卡片上叠加大面积实时模糊。
- 模糊只负责层级与聚焦，不能用来隐藏低质量图片，也不能让关键文本悬浮在无法预测亮度的背景上。

## 响应式要求

断点以内容是否需要重排为准，建议基线为移动端 `<768px`、平板 `768px-1199px`、桌面端 `>=1200px`，不能只针对单一设备宽度写死布局。

桌面端：

- 内容最大宽度约束，页面保持通透但不空旷。
- 图片瀑布流 3 到 5 列。
- 导航展示完整菜单。
- 正文阅读宽度控制在约 `68ch-76ch`，宽屏不能把文章拉成难以阅读的超长单行。

平板端：

- 图片瀑布流 2 到 3 列。
- 文章卡片减少列数。
- 筛选栏可折叠。

移动端：

- 图片瀑布流 1 到 2 列。
- 顶部导航切换为菜单抽屉。
- 搜索、语言、主题入口必须容易点击。
- 不得横向溢出。
- 文字不得遮挡或挤出容器。
- 触控目标最小约 `44px × 44px`，并处理安全区、横竖屏切换、软键盘和移动浏览器地址栏高度变化。
- 瀑布流列宽、工具栏、固定按钮和预览控件使用稳定尺寸约束，加载内容、翻译文案或 hover 状态不得推动整体布局跳动。

## 视觉方向与代码规范

首版设计原则：**代码简洁易懂、视觉效果丰富细腻、合理使用装饰元素提升体验**。

### 代码规范（核心要求）

- **变量命名清晰易懂**：使用有业务含义的中文注释和语义化命名，避免 `a`、`tmp`、`data1` 等无意义命名
- **代码结构简洁**：避免过度抽象和嵌套，保持可读性，单个函数/组件不超过 150 行
- **组件职责单一**：每个组件功能明确，易于维护和复用
- **类型定义完整**：TypeScript 类型清晰准确，避免 `any`，复杂类型提取为独立类型定义
- **注释适度精准**：复杂逻辑、业务规则、边界条件必须注释，简单的增删改查不过度注释
- **目录结构清晰**：按功能模块组织，组件、工具、类型、样式分离

**页面级动画：**
- ✅ 页面切换平滑过渡动画（fade + slide，支持前进后退不同方向）

- ✅ 首次进入页面的渐入动画（stagger 延迟）

- ✅ 半透明背景 + 高斯模糊（`backdrop-filter: blur(12px)`）

- ✅ 移动端菜单抽屉滑入滑出动画
- ✅ 激活菜单项下划线滑动动画

**图片相关动效：**
- ✅ 图片卡片悬停轻微缩放（scale 1.02-1.05）和阴影增强
- ✅ 图片懒加载：模糊占位 → 渐进清晰效果
- ✅ 图片预览浮层：淡入淡出 + 高斯模糊背景
- ✅ 预览浮层支持左右滑动切换图片，带缓动效果
- ✅ 瀑布流图片进入时 stagger 动画（依次淡入）

- ✅ 筛选条件切换时内容交叉淡入淡出

- ✅ Toast 通知从右上角滑入、自动淡出
- ✅ 下拉刷新拉伸回弹动画

**主题与语言切换：**
- ✅ 主题切换全局颜色平滑渐变（0.3s）
- ✅ 语言切换保留滚动位置和筛选状态
- ✅ 切换时避免闪烁，首屏加载前应用主题

**装饰性视觉增强（适度使用）：**
- ✅ **首页背景装饰**：可使用柔和的渐变网格、几何图案或光晕效果作为背景，不能遮挡主要内容
- ✅ **光标跟随效果**（可选）：鼠标移动时卡片轻微倾斜（tilt effect），增强空间感
- ✅ **滚动视差**（可选）：首页背景装饰元素轻微视差，速度不超过主内容的 0.5 倍
- ✅ **粒子/星空背景**（可选）：深色主题下可在页面背景使用轻量级星空或粒子效果，必须性能友好
- ✅ **鼠标光标光晕**（可选）：深色主题下鼠标周围柔和的光晕效果
- ✅ **数据可视化动画**：统计数字滚动增长动画（countup）
- ✅ **波纹扩散效果**：点击按钮时的 ripple 效果

**装饰元素使用原则：**
1. 装饰效果不能影响内容可读性
2. 装饰动画必须性能友好，不阻塞主线程
3. 移动端可选择性禁用部分装饰效果以保证性能
4. 所有装饰效果支持 `prefers-reduced-motion` 关闭
5. 装饰元素的色彩与整体主题协调，不喧宾夺主

### 视觉设计要求

**首页布局：**
- **首页以图片瀑布流为主视觉**，直接展示真实的公开图片资源
- 可在页面背景添加柔和的装饰元素（渐变、几何图案、光晕等）
- 半透明玻璃导航栏，滚动时高斯模糊背景
- 清爽内容门户风格，精心设计的配色和间距
- 文章卡片注重阅读体验，合理的信息密度
- 桌面端与移动端同时优化，响应式布局完美适配

**细节规范：**
- 卡片圆角：大卡片 `12px`，小元素 `8px`，输入框 `6px`
- 导航与工具按钮使用 Lucide React 图标并提供 tooltip
- 高斯模糊用于导航栏、浮层背景、图片预览遮罩和下拉菜单
- 悬停效果使用轻微缩放（scale 1.02-1.05）和阴影增强
- 过渡动画时长：快速交互 150-200ms，中等交互 250-300ms，页面切换 350-400ms
- 缓动函数优先使用 `cubic-bezier(0.4, 0.0, 0.2, 1)` 或 Tailwind 的 `ease-out`/`ease-in-out`
- 长单词和三语言文案必须安全换行
- 支持 `prefers-reduced-motion: reduce` 用户偏好

**动画性能要求：**
- 只动画 `transform` 和 `opacity`，避免触发重排
- 复杂动画使用 `will-change` 提示浏览器优化
- 滚动监听使用 `IntersectionObserver` 而非 `scroll` 事件
- 装饰性动画使用 `requestAnimationFrame`
- 图片懒加载使用原生 `loading="lazy"` 或 Next.js Image

## 前端服务封装

需要新增 C 端专用 API 封装：

- `src/services/publicApi.ts`
- `src/types/publicContent.ts`
- `src/config/constants.ts`

请求规则：

- 只请求 `/api/public/*`。
- GET 请求可做有限重试。
- 不携带后台写操作能力。
- 错误状态需要映射到 C 端可读的空状态或错误页。
- 服务端请求和客户端增强请求都必须设置超时与取消信号；只对网络瞬时错误和 `5xx` 做有限退避，不重试 `400`、`404` 等确定性结果。
- SEO 主数据优先在 Server Component 获取；只有筛选增强、预览浮层和“加载更多”使用客户端状态。
- API 基础地址、站点地址和媒体地址通过集中配置校验，不在组件中散落字符串拼接。

## 内容渲染要求

文章内容：

- 首期按 B 端现状支持经过白名单清洗的 HTML；不把同一字段同时猜测为 HTML 和 Markdown。
- 支持文章内图片安全展示。
- 自动生成目录锚点。
- 长文章显示阅读进度。
- 标题锚点必须稳定、唯一，并处理重复标题、中文标题和空标题；目录与正文 ID 一一对应。
- 外链使用安全的 `rel`，正文链接、图片和视频 URL 只允许明确协议；禁止脚本、表单、任意 iframe 和内联事件。
- 本地媒体必须经过公开资源鉴权重写；外部媒体加载失败时显示不遮挡正文的降级状态。
- 视频首期只允许浏览器安全格式和受控来源，默认 `preload="metadata"`，不自动播放。

图片内容：

- 使用响应式图片尺寸。
- 支持模糊占位。
- 支持预览大图。
- 失败图片显示降级占位。
- API 返回宽高或宽高比，渲染前预留空间；首屏关键图片可 `priority`，其余图片懒加载并提供正确 `sizes`。
- 低清缩略图可作为模糊占位，但不能把完整大图先下载后再用 CSS 缩小伪装成占位。

## 性能与缓存要求

- 以生产构建和常规移动网络为基线，目标 Core Web Vitals：LCP `<=2.5s`、CLS `<=0.1`、INP `<=200ms`，以可重复的本地或部署环境测量结果为准。
- 首页首屏只优先加载一个主要视觉资源；瀑布流、推荐区和文章图片按视口懒加载。
- 列表与详情采用服务端缓存或 Next.js revalidation；后台发布、取消发布后触发对应 tag/path 失效，若暂不实现主动失效，公开缓存 TTL 不得超过 `60s`。
- 媒体使用内容协商、条件请求和浏览器缓存；更新同一文件内容时必须改变 ETag/Last-Modified，不能让旧内容永久缓存。
- 控制首屏 JavaScript，不把文章正文、纯展示卡片和 metadata 组件无故标记为 Client Component。
- 字体优先使用系统字体或本地托管子集；禁止首屏依赖不可控的第三方字体请求。
- 高斯模糊、阴影和进入动画需要在中端移动设备验证滚动流畅度，性能不足时优先降低模糊和动效强度。

## 可访问性要求

- 所有图标按钮提供 `aria-label`。
- 主题、语言、搜索按钮可键盘访问。
- 图片预览浮层支持 `Esc` 关闭。
- 颜色对比度满足常规阅读需求。
- 焦点样式清晰。
- 页面使用语义化标题层级、导航、主内容、文章、时间和面包屑结构；每页只有一个清晰的 `h1`。
- 提供“跳到主要内容”入口；路由切换后更新页面标题并把焦点移动到合理位置，不让键盘用户迷失。
- 浮层打开后锁定底层交互并管理焦点循环，关闭后把焦点还给触发按钮。
- 图片必须使用 B 端说明、文章上下文或文件名生成有意义的 `alt`；纯装饰图使用空 `alt`，不能把所有图片都写成“图片”。
- 错误、加载、搜索结果数量和语言切换结果在需要时通过可访问状态区域通知，不能只靠颜色或动画表达。
- 目标至少满足 WCAG 2.2 AA 的键盘、焦点、对比度和名称角色值要求。

## 环境变量与运行约定

`portal/.env.example` 至少说明：

- `NEXT_PUBLIC_API_BASE_URL`：浏览器可访问的后端地址，开发默认 `http://localhost:8080`。
- `NEXT_PUBLIC_SITE_URL`：C 端绝对站点地址，开发默认 `http://localhost:3001`，生产必须是最终 HTTPS 域名。
- `NEXT_PUBLIC_ENABLE_CUSTOMER_CHAT`：是否启用客服入口，默认 `false`。
- `PORTAL_REVALIDATE_SECONDS`：服务端内容缓存秒数，默认 `60`，必须校验为合理正整数。

要求：

- `NEXT_PUBLIC_*` 中禁止放密钥、后台 Cookie、数据库地址或其他服务端秘密。
- `package.json` 至少提供 `dev`、`build`、`start`、`typecheck`、`lint` 和 `docs`；`dev`、`start` 默认使用端口 `3001`。
- 生产启动时校验站点地址和 API 地址；SEO 配置缺失或仍为 localhost 时输出明确错误，不能静默生成错误 canonical。
- 后端生产环境把 C 端与 B 端域名同时加入明确的 `CORS_ALLOWED_ORIGINS`，不得继续使用通配符配置。
- 根 `README.md` 同步增加 C 端安装、环境变量、启动、构建、三应用联调和公开 API 说明。

## 可观测性与隐私

- 首期不接入第三方广告或跨站追踪脚本；语言 Cookie、主题偏好和可选客服会话之外不新增不必要的客户端标识。
- 后端可沿用现有访问分析记录公开 API 的状态码、耗时和设备概况，但不得在日志中记录文章正文、文件路径、客服令牌或完整敏感查询内容。
- 搜索关键词如需分析，应先做长度限制和脱敏策略；默认不把完整关键词写入额外日志。
- 客服入口启用时只使用现有客服聊天接口、访客令牌和断线恢复规则，不接入内部聊天 `/api/internal-chat/*`，并在隐私说明中披露会话用途。
- C 端错误边界记录可定位的错误码和路由，不把用户内容、响应正文或服务器秘密发送给浏览器控制台。
- 上线前检查 `robots.txt`、CSP、CORS、缓存头、Cookie 属性和隐私说明与实际行为一致。
