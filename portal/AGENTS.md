# portal/AGENTS.md

## 操作前规则读取

- 每次收到新的用户任务、补充要求或任务方向变化后，在对 `portal/` 执行任何文件检索、读取、命令、编辑、构建、测试、提交或推送之前，必须重新读取仓库根目录的 `../AGENTS.md` 和本文件。
- 涉及门户业务实现时还必须重新读取 `../docs/portal-requirements.md`；不得仅依赖历史对话、上下文摘要或之前读取过的规则。

## 适用范围与优先级

- 本文件适用于 `portal/` 及其全部子目录，并补充仓库根目录 `AGENTS.md`。
- 发生冲突时遵循 system、developer、用户指令、根 `AGENTS.md`、本文件的优先级；更深目录中的 `AGENTS.md` 可继续补充其局部规则。
- C 端产品与技术基线以 `../docs/portal-requirements.md` 为准。实现前先阅读需求文档，不得只依据页面截图猜测业务规则。
- 当前任务编号必须根据最新 Git 提交和根目录规则确定：同一尚未提交任务的补充修改沿用当前 `Pn`，当前任务提交后，下一个独立任务递增为新的 `Pn`。

## 当前实现状态

- `portal/` 已是可安装、启动、构建和容器部署的 Next.js 16 应用，拥有独立 `package.json`、锁文件、App Router 源码、Dockerfile、三语言资源和 TypeDoc 配置。
- 当前实现包含文章、图片、资源、日常、分类、搜索、文章详情、图片标签与互动、RSS、sitemap 和 robots；`/{locale}` 当前跳转到 `/{locale}/images`，图片瀑布流是第一屏主入口。
- C 端支持后端会话登录恢复和 18R 开关。匿名请求排除 18R 内容；只有有效 HttpOnly 会话且 `portal-r18=1` 时公开接口才返回 18R 内容。
- 仓库根 `docker-compose.yml` 已编排门户服务，默认端口为 `3001`；部署配置变化时同步检查 Compose、根 `.env.example`、README 和部署说明。

## 项目定位与业务边界

- `portal/` 是面向普通访问者的 C 端内容门户，展示后端判定可公开的文章、图片和文件资源。
- `backend/` 是唯一业务数据来源；C 端不得直连 SQLite、扫描上传目录、复制后台数据或实现第二套内容存储。
- 内容请求只能使用 `/api/public/*`。登录、会话恢复和退出可使用 `/api/auth/login`、`/api/auth/session`、`/api/auth/logout`，但不得调用后台写接口、读取或持久化会话 ID。
- 公开文章条件为 `is_private=0 AND status='已发布'`；公开文件条件为 `is_private=0 AND deleted_at IS NULL`。前端不得自行放宽这些条件或 18R 过滤。
- 客服入口只能复用现有客服聊天边界，不得调用或混用 `/api/internal-chat/*`、内部聊天状态和后台鉴权。
- C 端不提供文章、文件编辑、付费或投稿能力；日常内容通过独立的 `/{locale}/daily/publish` 富文本页面发布。支持通过 `/api/auth/register/*` 完成账号、密码和邮箱验证码注册，后端固定分配最低权限 `viewer` 角色。图片评论只允许登录用户通过 `/api/public/files/:id/comments` 发送纯文本，并由后端公开条件和会话鉴权共同约束。

## 技术栈与运行约定

- `portal/` 本身是 C 端项目根目录，`package.json` 名称为 `portal`；禁止创建第二层项目目录。
- 当前技术栈为 Next.js 16 App Router、React、strict TypeScript、Tailwind CSS 4、Lucide React 和 `next-intl`。
- 独立维护 `package.json` 与 `package-lock.json`，依赖只在 `portal/` 安装；禁止在仓库根目录混装依赖。
- 默认开发地址为 `http://localhost:3001`，后端默认地址为 `http://localhost:8080`。
- 浏览器可见后端地址读取 `NEXT_PUBLIC_API_BASE_URL`，站点绝对地址读取 `NEXT_PUBLIC_SITE_URL`；`NEXT_PUBLIC_*` 中禁止放密钥、数据库地址、后台 Cookie 或其他秘密。
- 新增依赖前先确认现有平台能力能否完成需求。开源代码必须核对许可证，并在 `THIRD_PARTY_NOTICES.md` 记录来源、许可证、使用范围和修改说明。

## 目录职责

- `app/`：只放 App Router 路由入口、布局、metadata、全局错误/加载页面和全局样式入口。
- `src/components/`：共享展示组件和具备明确领域职责的交互组件。
- `src/services/`：`/api/public/*` 请求、超时、错误映射和缓存选项。
- `src/types/`：公开文章、图片、资源、分页和错误响应等共享类型。
- `src/config/`：站点、路由、语言、主题、环境变量和业务白名单常量。
- `src/i18n/`：语言路由、消息资源、语言校验和格式化配置。
- `src/content/`：富文本清洗、正文媒体重写、目录和锚点逻辑。
- `src/theme/`：主题定义、CSS 变量映射、首屏初始化和持久化逻辑。
- `src/styles/`：按职责拆分的全局增强样式；页面私有样式应靠近所属组件。
- `src/utils/`：无 React 上下文、无业务状态的纯工具函数。
- 不得把服务请求、复杂状态、富文本处理和完整页面 UI 堆在单个路由文件中，也不得建立与 App Router 冲突的 `src/pages/`。

## 代码注释与命名

- 业务源码中的文档注释和解释性行内注释必须使用简体中文；协议名、库名、标识符、CSS 属性和代码字面量可以保留英文。
- 类型、接口、React 组件、钩子、服务函数、共享状态、模块级常量、页面内部函数、事件回调和局部业务变量都必须使用中文 JSDoc/TypeDoc 或解释性注释。
- 注释必须说明声明保存的业务内容、函数执行的行为、参数与返回值，或状态变化及副作用。不得使用“保存数据”“处理信息”“执行操作”等没有实际业务含义的注释。
- 页面或组件外层已有说明不能代替内部声明的注释。复杂条件只在能解释业务原因或安全边界时增加行内注释，避免逐行复述代码。
- 使用 `publishedArticles`、`selectedLocale`、`portalImageWidth`、`loadPublicResources` 等可表达领域含义的名称。
- 不得新增 `data`、`info`、`item`、`handle`、`temp` 等宽泛名称；循环元素也应使用 `article`、`imageFile`、`resourceCategory` 等具体名称。
- 布尔值优先使用 `is`、`has`、`can`、`should` 前缀；事件函数使用能够说明动作与对象的名称，例如 `openImagePreview`、`changePortalTheme`。
- API JSON 字段保持 camelCase，URL、权限编码、语言代码和业务状态不得使用翻译后的显示文案作为内部键。
- 翻译 JSON、框架生成文件和第三方源码不强行添加注释；业务声明仍必须通过语义化键名、类型和相邻源码注释表达含义。
- TypeDoc 配置位于 `typedoc.json`；公共类型和服务契约变化后必须执行文档生成并修复有效警告。

## App Router 与 React 约定

- 使用真实 URL 路由和 Server Component，不沿用 B 端 `activePage` 客户端页面切换模型。
- 默认使用 Server Component。只有依赖浏览器 API、事件、局部交互状态或客户端生命周期的最小边界才添加 `'use client'`。
- SEO 主内容在服务端获取并渲染；筛选增强、加载更多、主题/语言控件和图片预览等交互可在客户端实现。
- 共享 API 类型与请求逻辑只能定义一次。组件不得直接散落 API 地址、响应字段猜测或重复 `fetch` 封装。
- GET 请求必须支持超时和取消；只对网络瞬时错误和 `5xx` 做有限重试，不重试 `400`、`404` 等确定性结果。
- 页面、筛选、预览和异步内容使用稳定尺寸与响应式约束，加载、hover、翻译文本或错误状态不得造成明显布局跳动。
- 不在渲染期间读写 `window`、`document` 或 `localStorage`；需要首屏主题时使用经过审查的初始化脚本并避免水合不一致。

## 公开 API 与内容安全

- 前端不得仅凭隐藏按钮、路由判断或响应字段过滤承担安全职责；匿名可见性必须由后端公开接口再次校验。
- 不得向公开响应、日志、错误页或客户端状态暴露 `storageName`、物理路径、所有者 ID、后台权限和内部错误堆栈。
- 不得直接渲染后端原始 HTML。正文必须经过需求文档规定的白名单清洗；禁止把未清洗内容传给 `dangerouslySetInnerHTML`。
- 本地文章媒体只能使用经过公开条件校验并重写后的 `/api/public/files/*` 地址，禁止拼接上传目录或后台预览地址。
- 外部媒体首期只接受受控 `https://` 地址；禁止新增可请求任意 URL 的服务端代理，避免 SSRF。
- SVG、HTML、脚本、可执行文件和无法确认真实类型的文件不得匿名内联展示。下载和预览必须使用后端返回的受控 URL。
- 外链使用安全 `rel`，用户内容不得生成任意 `script`、事件属性、表单、iframe 或危险协议。
- 修改公开 API 路径、字段、缓存、鉴权或错误契约时，同步检查 `backend/`、B 端文章/文件字段、`../docs/api/openapi.yaml`、根 `README.md` 和 C 端所有调用方。

## SEO 约定

- 图片入口、文章、资源、分类和详情页必须输出服务端可见正文，不得依赖客户端请求后才出现主要内容。
- 每个可索引页面提供唯一 title、description、canonical 和必要的 Open Graph 信息；结构化数据必须与页面可见内容一致。
- 规范路由使用 `/{locale}/...`。`/` 只根据已校验偏好跳转，不支持的语言返回 `404`。
- sitemap、robots、RSS 和 JSON-LD 只能包含当前满足公开条件的资源；内容变为私密、未发布或软删除后必须按缓存约定失效。
- 搜索结果、预览状态、错误页和不稳定筛选组合使用 `noindex`；第一页不得同时以无参数和 `?page=1` 两个 canonical 被索引。
- 文章正文实际语言使用 `contentLocale` 标记。没有真实翻译关系时不得伪造文章详情 `hreflang`。
- 生产构建必须使用最终 HTTPS `NEXT_PUBLIC_SITE_URL`，不能静默生成 localhost canonical。

## i18n 约定

- 支持 `zh-CN`、`en-US`、`ja-JP`；本项目明确以 `zh-CN` 为默认语言、源文案和最终回退语言。
- URL 语言段是当前页面语言的唯一事实来源；`portal-locale` Cookie 只保存经过支持列表校验的 BCP 47 语言代码。
- 所有用户可见 UI 文案必须使用语义翻译键，包括导航、按钮、占位符、校验、加载、空、成功、错误、离线、超时、tooltip 和无障碍名称。
- 翻译键按领域命名，例如 `navigation.articles`、`images.empty.title`，不得使用 `text1`、`button2` 或中文句子作为键。
- 使用命名占位符和复数规则，不拼接翻译片段。日期、时间、数字、文件大小、百分比和列表使用 `next-intl` 或 `Intl.*` 格式化。
- 语言选择器显示清晰语言名称，不能只使用国旗；切换语言时尽量保留筛选、分页、滚动位置和当前可等价内容。
- 用户生成的标题、正文、分类和文件说明保持原文，不当作翻译键，也不进行未经确认的自动翻译。
- 新增或修改页面时同时补齐三种语言，并检查英文和日文长文案在移动导航、按钮、筛选栏、卡片和对话框中不截断、不重叠。

## 主题、样式与动画

- 主题使用 CSS 变量，至少支持浅色、深色、海洋品牌和跟随系统；持久化键固定为 `portal-theme`，不得覆盖 B 端 `admin-theme`。
- 主题必须在首屏渲染前应用，切换时避免大面积闪烁，并同步 `color-scheme` 与移动浏览器 `theme-color`。
- 高斯模糊只用于导航、搜索、筛选工具栏和预览背景等明确层级；必须提供无 `backdrop-filter` 时的纯色回退。
- 不在长列表每张卡片上叠加大面积实时模糊；移动端降低模糊强度，正文和关键操作始终保持足够对比度。
- 常规动画控制在约 `160ms-280ms`，优先使用 `transform` 和 `opacity`；动画不得阻塞点击、导航、返回或产生横向溢出。
- 所有页面切换、侧栏、抽屉、浮层和卡片动画必须支持 `prefers-reduced-motion: reduce`，减少动态效果时关闭或显著弱化。
- 使用 Lucide 图标实现常见工具操作，图标按钮提供 tooltip 和 `aria-label`；不重复手绘已有图标。
- 卡片圆角默认不超过 `8px`。页面区块不包装成漂浮卡片，不在卡片内继续嵌套卡片。
- 不使用装饰性渐变球、光斑或纯氛围插画代替真实内容。当前图片入口优先展示真实公开资源，并在首屏露出后续内容。
- 字号不随视口宽度连续缩放，字距不使用负值；三语言长文本必须换行并保持容器稳定。

## 响应式与可访问性

- 同时验证桌面、平板和移动布局；禁止横向溢出、文本遮挡、控件裁切、不可点击区域和双重滚动条。
- 图片瀑布流必须预留宽高比，移动端 `1-2` 列、平板 `2-3` 列、桌面 `3-5` 列，并保证 DOM 阅读顺序可理解。
- 图片页使用后端分页作为内部批次协议，不显示分页按钮；通过 `IntersectionObserver` 在接近底部时预加载下一批，追加数据时保持已加载卡片的列归属稳定。
- 默认每批请求 24 张、上限 50 张；缩略图先占位，中图进入瀑布流队列，预览浮层才请求当前原图。队列并发为移动端 2、宽视口 4；只取消未完成的预加载请求，已加载卡片保持挂载，不因滚动离开视野而卸载。
- 预览浮层的复制 URL、下载、点赞、标签和评论按钮必须复用公开接口；互动读取可匿名，写入要求登录，评论限制为最多 500 个 Unicode 字符。
- 触控目标至少约 `44px × 44px`；hover 只作为鼠标设备增强，核心操作在触摸设备上必须始终可发现。
- 页面保持正确标题层级，每页一个清晰 `h1`，并使用 `nav`、`main`、`article`、`time` 等语义结构。
- 提供跳到主要内容入口、可见焦点和键盘操作；浮层管理焦点循环，关闭后焦点返回触发元素。
- 图片提供有意义的 `alt`，纯装饰图使用空 `alt`；颜色和动画不能成为表达状态的唯一方式。
- 目标至少满足 WCAG 2.2 AA 的键盘、焦点、对比度和名称角色值要求。

## 性能与资源约定

- 使用 Next.js Image 或受控媒体优化链路，并提供准确 `width`、`height`、`sizes`；首屏只优先加载一个主要视觉资源。
- 列表和详情使用服务端缓存或 revalidation。取消发布后必须主动失效，或在不超过需求文档约定的短 TTL 内失效。
- 纯展示正文、metadata 和内容卡片不得无故成为 Client Component；控制首屏 JavaScript 和第三方脚本。
- 字体优先使用系统字体或本地托管资源，首屏不得依赖不可控第三方字体。
- 性能目标为 LCP `<=2.5s`、CLS `<=0.1`、INP `<=200ms`；高斯模糊和动画必须在移动设备视口实际检查。
- 不手工编辑或提交 `.next/`、`node_modules/`、`tsconfig.tsbuildinfo`、`next-env.d.ts`、运行日志和其他生成物。

## 测试、数据隔离与验收

- C 端最小验证包括 `npm run typecheck`、`npm run lint`、`npm run docs` 和 `npm run build`；新增测试脚本后同步执行相关单元与集成测试。
- 涉及后端公开 API 时执行 `go test ./...`、`go vet ./...`；涉及 B 端文章或文件能力时执行 B 端严格类型检查和生产构建。
- 所有联调、脚本和浏览器验收使用当前任务对应的 `.workspace-temp/p<n>-portal/` 目录，其中 `n` 为当前 `Pn` 的数字部分；目录内使用独立 SQLite、上传目录、日志和中间产物。
- 严禁删除、覆盖、重置、清空或使用真实业务 API 批量清理 `backend/data/`、SQLite WAL/SHM 和 `backend/uploads/`。
- 视觉或交互变更必须使用当前 Codex 环境的官方 Browser 插件检查桌面与移动端，不以第三方浏览器工具替代。
- 至少检查 `1440×900`、`768×1024`、`390×844` 和 `360×800`，覆盖三语言长文案、主题、减少动态效果、慢图、破图、空数据和错误状态。
- 验收前检查控制台错误、hydration、横向溢出、焦点、图片像素可见性、metadata、sitemap、robots 和公开资源权限边界。

## 改动保护与 Git 流程

- 保留工作区已有改动，只修改当前任务所需文件。遇到不属于当前任务的改动时忽略并保留，不能回退或覆盖。
- 临时文件只放当前任务对应的 `.workspace-temp/p<n>-portal/`；除非用户明确要求，不修改或删除 `output/` 中的用户成果。
- 每次改动完成后先报告当前 `Pn`、关键变化、验证结果、隔离环境和残余风险，等待用户验收。
- 用户明确回复验收通过、可以提交或可以推送之前，不得暂存、提交或推送。
- 获得验收后使用明确路径暂存，检查 `git diff --cached --check` 与 `git status --short`，避免带入业务数据、生成物或无关改动。
- 提交摘要遵循根规则的 `P<number> <type>:` 格式；推送默认同时确认 GitHub `origin` 和 Gitee `gitee`。
